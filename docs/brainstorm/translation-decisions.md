# 翻译范围脑暴

- 日期：2026-10-15；主持：Remy；形式：Producer 单线程模拟六角色讨论，不是独立子代理审查或投票证据。
- 输入：给定 SHA、用户“只翻译不改功能”约束、范围证据、40 份一方 Markdown 清单。

## 六个视角

| 角色 | 主张 | 验证责任 |
| --- | --- | --- |
| Kira / 产品 | 默认简体中文文档和设置应完整；不能用 FAQ 代替未翻译设置 | 逐入口核对覆盖率与不做范围 |
| Milo / 体验 | 直接替换可见文案最省改动，保留技术英文；首屏中文不应改变菜单布局 | 字形、裁切、帮助、禁用状态、所有缩放档 |
| Nova / 架构 | 可见标签混有内部身份与分派，不能默认纯数据替换安全 | ID 栈、strcmp、日志共享数据流 |
| Sage / 实现 | 复用现有 C++/ImGui，先用清单和一个 pwsh 验证器限制字符串槽位 | 负向样例、未知语法 fail closed、无源码 token 扩张 |
| Ivy / QA | 静态绿不证明中文可见或功能一致；必须留真实构建与游戏链路 | Windows 构建、GPU/游戏、旧 INI 与菜单交互对比 |
| Remy / 制作 | 不移植 Aurora，不自动提交、不调用子代理；授权冲突不能藏到验收末尾 | 预定义 gates、串行范围、未运行证据与阻塞记账 |

## 分歧一：直接替换文案是否足够

| 回合 | 意见与反驳 | 结算 |
| --- | --- | --- |
| Milo | 保留 `##2` 就能保住按钮身份；用户可自选字体 | 作为待证假设，不能作实现依据 |
| Nova | 目标 `ImHashStr` 只有 `###` 重置，且井号仍入哈希；NR `DeferredSlider` 用英文 label 做 strcmp 与 pending key | 直接替换和仅保留后缀均不足以证明契约 |
| Sage | 可先考虑 ASCII 转义字节，避免工程 `/utf-8` 修改；但该方案不提供中文字形，也不保持原 ID | 编码候选留给字节探针，不能据此关闭字体风险 |
| Ivy | 用户手动选字体不满足默认中文可用；HQ、非 HQ、自定义字体均需实际验收 | 保留完整 UI 任务，字体/ID 最小支持待授权，不复制 Aurora 回退实现 |

## 分歧二：是否删掉历史与开发文档以缩 Sprint

| 回合 | 意见与反驳 | 结算 |
| --- | --- | --- |
| Remy | 核心说明优先，旧 review/实验说明可否排到以后 | 作为分组提案，未删范围 |
| Kira | 用户要求完整，历史文档仍含风险和支持边界，删掉会造成错误覆盖声明 | 40 份全部纳入，按 B1/B2 分组，不作无依据延期 |
| Sage | 根文档 8 份一组，其余 32 份一组，保留已有中文及所有原文 | 新建镜像，不改旧文档；同一术语表与 coverage 使串行更合适 |
| Ivy | 文件有中文不等于段落完整，代码块/技术串可以合法保留英文 | 覆盖率分母按自然语言单元，保护项有理由且不得排除整篇 |

## 分歧三：安装器与中文首页

| 意见 | 裁决 |
| --- | --- |
| Milo 希望把实际 BAT 默认变中文，并把 README 首页改中文 | 默认范围尚无安装脚本改写授权，且无 chcp 不能保证跨代码页；不直接改写 |
| Kira 要保留完整安装文案信息 | A1/C1 完整登记并提供中文对照；实际脚本写入保持条件项，不宣称安装器已汉化 |
| Remy 要求英文 README 原字节保留 | 使用新增 README.zh-CN.md；不更换英文首页、不搬 Aurora 品牌或功能承诺 |

## 已定与未定

- 已定：翻译不改功能、英文原文保留、全量文档、串行 5 节点、一个 pwsh 验证器、无提交/远程操作。
- 未定：字体/内部 ID/共享日志的局部支持授权、实际安装器范围与编码、Windows/GPU 资源、脏工作树正式 revision 协议。
- 第一便宜检查：Dev 先为 label/strcmp/完整 ID 建立失败样例；字体先查实际译文字形和目标 atlas，不先写大规模译文。
- 结论在“所有中文译文字形均已由目标默认字体覆盖，且原 ID/分派可用纯字符串表示严格保持”时需要重估；尚无该证据。
